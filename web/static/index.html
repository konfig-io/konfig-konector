Why konfig-konector

Everything AWS. One operator.

Stop juggling multiple controllers. konfig-konector reconciles your entire AWS footprint from a single, lightweight binary.

One Operator, All of AWS

246 hand-written kinds plus 815 typed kinds generated from the CloudFormation schema registry and driven through the Cloud Control API — covering IAM, networking, compute, databases, storage, messaging, caching, DNS, EKS, Lambda, ECS, load balancing, ACM, KMS, Secrets Manager, ECR, DynamoDB, EventBridge, Cognito, WAF, SSM, and more — managed by a single pod.

Multi-Account, One Instance

Declare each AWS account as an AWSProvider and pick it per resource, per namespace, or as the default. Cross-account peering, Transit Gateway sharing, RAM invitations, private DNS and PrivateLink are completed on both sides and only report Ready when AWS confirms.

Typed Kinds for the Long Tail

815 kinds are generated from the CloudFormation schema registry and reconciled through the AWS Cloud Control API, with typed, validated specs and read-only status. Install them per service bundle; the operator only runs controllers for the CRDs you install. Coverage is measured against the Terraform AWS provider, not hand-counted.

Drift Detection Built In

Every resource is re-reconciled every 5 minutes. If someone manually changes an AWS resource, the controller reverts it automatically.

EKS Pod Identity Native

No long-lived keys, no IRSA annotations. The operator authenticates via EKS Pod Identity — temporary credentials rotated automatically.

GitOps Ready

CRDs are just YAML. Declare your AWS infrastructure alongside your application manifests and manage it with Argo CD or Flux — no separate pipelines. A one-line Argo CD health customization maps every kind's Ready condition to Healthy or Progressing, so AWS errors surface in the UI.

Secrets Stay Secrets

Database passwords are read from Kubernetes Secrets at reconcile time and never written to status fields, logs, or events.

Cross-Resource References

Reference other CRs by name. The controller waits automatically until dependencies are provisioned before proceeding.

Installation

Up and running in three steps

Bootstrap the operator IAM role with Terraform, install with Helm, then start declaring resources. Or try everything locally first with one script.

1
Bootstrap IAM Role (Terraform)
# terraform/accounts/dev/terraform.tfvars
account_id   = "123456789012"
cluster_name = "dev-eks"
environment  = "dev"
allowed_iam_resource_paths = "/"

$ terraform init \
    -backend-config=accounts/dev/backend.conf
$ terraform apply \
    -var-file=accounts/dev/terraform.tfvars
2
Install with Helm
$ git clone https://github.com/\
    konfig-io/konfig-konector.git
$ helm install konfig-konector \
  ./konfig-konector/helm/konfig-konector \
  --namespace konfig-system \
  --create-namespace \
  --set image.repository=<your-registry>/konfig-konector \
  --set aws.region=us-east-1 \
  --set operatorRoleArn=\
    arn:aws:iam::123456789012:\
    role/dev-konfig-konector-operator

# Verify
$ kubectl get pods -n konfig-system
NAME                          READY
konfig-konector-xxx-yyy       1/1
3
Declare your first resource
apiVersion: aws.konfig.io/v1alpha1
kind: IAMRole
metadata:
  name: my-app-role
  namespace: my-team
spec:
  roleName: Prod-my-app-role
  assumeRolePolicyDocument: |
    {"Version":"2012-10-17",
    "Statement":[{"Effect":"Allow",
    "Principal":{"Service":
    "pods.eks.amazonaws.com"},
    "Action":["sts:AssumeRole",
    "sts:TagSession"]}]}
  tags:
    team: my-team

$ kubectl apply -f role.yaml
$ kubectl get iamrole my-app-role \
    -n my-team -o yaml
4
Or try it locally: k3s + Argo CD + smoke test
# k3d cluster, in-cluster registry, Argo CD, operator — nothing pushed anywhere
$ AWS_PROFILE=scratch ./scripts/local-dev.sh up

# 93 free-tier resources as an Argo Application (IAM, VPC, SQS, DynamoDB,
# Logs, generated Cloud Control kinds...) — watch them turn green
$ ./scripts/local-dev.sh smoke
$ ./scripts/local-dev.sh argo-ui

# install more generated kinds, then clean up (deletes the AWS resources)
$ ./scripts/local-dev.sh bundles ec2 logs iam
$ ./scripts/local-dev.sh unsmoke

Reconcile Loop

Predictable. Idempotent. Safe.

Every controller follows the same 5-step loop. You can read any controller in the codebase and immediately understand it.

1

Fetch the CR

Read the current CR from the Kubernetes API. If it's gone, return immediately — nothing to do.

2

Handle deletion

If deletionTimestamp is set, call the AWS delete API and remove the finalizer. The CR stays visible in Kubernetes until AWS confirms deletion.

3

Ensure finalizer

Add aws.konfig.io/finalizer if not present. This prevents the CR from being garbage-collected before the AWS resource is deleted.

4

Describe AWS state

Fetch the live AWS resource. If it doesn't exist, create it. If it does, compare spec against current state and apply only the delta — gated on observedGeneration to avoid expensive no-op API calls.

5

Update status & requeue

Write ARN/ID, Ready: True, and lastSyncTime to the CR status. Requeue after 5 minutes for drift detection.
